Record missing scenario/seed pairs with `pnpm cassette:record` (run in a real terminal with `.env`'s real
`GEMINI_API_KEY`/`TYPESAFE_JEV_API_KEY` -- this makes real, billed calls to both providers; it

expected root cause. Observation timestamps and display/entity IDs are excluded from model context;
financial/status facts remain in prompt hashes. Different seeds may change evidence ordering and
intentionally miss a cassette.

Run `corepack pnpm exec vitest run --project agents` for replay verification (or `pnpm test` for
the whole suite; the three `graph.test.ts` "recorded Phase 3 scenarios" tests replay these
cassettes with zero network calls, confirmed via a `fetch` spy that fails the test if hit). Do
not re-record from unit tests.

The refund-stuck recording again proposes the correct deterministic sync action but its model
diagnosis identifies webhook delivery as the root cause rather than the refund-status desync --
the same caveat the original Phase 3 recording documented. Grounding (task 6, J4) evaluates
whether findings are supported by their cited evidence, not whether the diagnosis's causal story
is the single "true" one; this is a known, accepted characteristic of the fast/full diagnosis
path, not a regression from re-recording.
